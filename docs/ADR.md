# Architecture Decision Records

> 근거: 기획서 v5. 각 ADR 끝의 §는 기획서 절 번호, W는 기획서 §16 "아직 모르는 것" 항목.

## 철학
- **손 없이 완결.** 대상자가 쓰는 경로에 필수 버튼을 두지 않는다. 이 조건을 깨는 기능은 머지하지 않는다.
- **안전이 편의보다 먼저.** "말 안 했는데 나옴"은 사고, "말했는데 안 나옴"은 다시 말하면 된다. 애매하면 안 나오는 쪽을 택한다.
- **데이터는 구조로 지킨다.** 정책 문구보다 아키텍처로 막는다 — 영상은 단말 밖으로 나가지 않고, 임의 텍스트 합성 경로는 존재하지 않는다.
- **상시 고정비를 만들지 않는다.** 관리형 API로 시작하고, 근거(품질 벤치마크·슬롯 상한)가 생기면 옮긴다.

### ADR-001: 상시 GPU 없이 Vercel + Supabase + ElevenLabs
**결정**: 웹·API는 Vercel(Node Runtime · icn1 · Fluid Compute), 인증·DB·스토리지·Realtime은 Supabase, TTS·클로닝은 ElevenLabs API.
**이유**: GPU 서버 고정비를 없앤다. Fluid Compute는 외부 API 응답 대기 중 Active CPU 과금이 멈춘다. Edge Runtime은 Node API 제한과 응답 시작 시간 제한이 있어 TTS 대기·스트리밍에 맞지 않는다.
**트레이드오프**: ElevenLabs 플랜 기본료와 voice 슬롯 상한(Pro 160 · Scale/Business 660)에 묶인다. 한국어 저품질 참조 음성의 클로닝 품질은 미검증(W3). §1, §5.2, §12.1

### ADR-002: 고정 문장 발화 경로는 단말에서 완결 + 사전 합성
**결정**: 구간 검출·정규화·인식·판정·재생을 브라우저에서 한다. 음성은 voice 등록·문장 추가 시점에 (문장 × voice)를 전부 합성해 단말에 내려둔다.
**이유**: 발화 순간 네트워크 왕복이 0회라 콜드스타트·네트워크 장애가 응급 경로에 끼지 않고, 오프라인에서도 등록 문장 전부가 약 0.6초 안에 나간다. 재생할 수 있는 것이 등록 문장뿐이라 클라이언트를 조작해도 할 수 있는 일이 없으므로 서버 권위 게이트가 필요 없다.
**트레이드오프**: 문장 추가·목소리 교체 때마다 재합성·재다운로드가 필요하다. 저가 태블릿의 연산 성능에 의존한다(W12). §5

### ADR-003: 고정 문장 트랙과 자유 문장 트랙 분리
**결정**: 자유 문장은 필수 목표지만 별도 트랙으로 둔다. 응급 발화는 고정 문장 트랙에서만. 자유 문장은 받아쓰기가 아니라 후보 3개 + 대화 맥락 + 대상자 확인 후 발화로 정의한다.
**이유**: 한국어 립리딩 기준선이 CER 약 32%(OLKAVS, 소리 낸 발화 기준)라 인식 결과를 그대로 소리 내면 안 된다. 확인 단계가 오발화 방지와 사칭 악용 방어를 겸한다.
**트레이드오프**: 자유 문장은 발화까지 수 초가 걸리고 오프라인에서 안 된다. 진입 방식이 미정이다(W14). §5.4, §14

### ADR-004: 인식 방식은 DTW 템플릿 vs 소형 1D-CNN 파일럿 비교 (미확정)
**결정**: 두 방식을 같은 파일럿 데이터로 비교해 정한다. 기준은 등록 문장 정확도, 자연 상태 10분 오발화, 문장당 필요 샘플 수, 문장 추가 후 사용 가능까지 시간, 저가 태블릿 연산 시간.
**이유**: Tier 0는 문장당 3회(12건)라 CNN을 처음부터 학습하기 어렵고 소량 학습 모델의 softmax 확신도는 과신한다. DTW는 학습이 없고 거리 기반 거절이라 NONE 데이터가 필요 없지만 자세·말 속도 변화에 민감할 수 있다.
**트레이드오프**: 확정 전까지 인식기 출력(`{label, score}`)과 `models.kind`가 두 방식을 모두 수용해야 한다. §4.3

### ADR-005: 판정 게이트 4단 · 보수적 임계값
**결정**: NONE·거리 초과·score < 0.70은 폐기, 0.70–0.90은 문장만 표시, 0.90 이상은 발화(수동 세션은 0.80).
**이유**: 두 오류의 비용이 비대칭이다. 문장만 표시하는 단계가 손 없는 취소 수단이 된다 — 다시 말하면 확정된다.
**트레이드오프**: 초기에는 "안 나옴"이 늘어난다. 임계값은 오발화 실측으로 보정한다. §4.1

### ADR-006: 이중 트리거 — 무조작 기본 + 수동 세션 옵션
**결정**: 기본은 무조작 자동 감지. 손을 쓸 수 있는 사용자를 위해 수동 ON/OFF 세션(화면 버튼·BLE 버튼·발 스위치·시선 고정 2초)을 옵션으로 둔다. OFF면 카메라 트랙을 정지한다.
**이유**: ALS·뇌졸중 대상자는 손을 못 쓸 수 있다. 수동 세션은 면회·진료 중 "지금은 말하지 않겠다"를 표시하는 수단도 된다.
**트레이드오프**: 모드 A는 카메라가 상시 동작한다. 브라우저는 화면이 꺼지면 카메라를 멈추므로 Wake Lock + 검은 화면으로 대신한다. §4, §3.4

### ADR-007: Google OAuth 단독 + 계정/대상자 분리
**결정**: 로그인은 Google OAuth만. 로그인 주체는 보호자 계정(account), 말하는 사람은 대상자(subject), 계정 1 : 대상자 N. 병상 태블릿은 영구 로그인 + 키오스크 모드.
**이유**: 손을 못 쓰는 대상자는 스스로 로그인할 수 없다. 고령 보호자도 안드로이드 기기에서 구글에 이미 로그인되어 있을 가능성이 높다.
**트레이드오프**: 구글 계정이 없는 보호자가 막힌다 — Stage 2에서 카카오 로그인 검토. §3.1

### ADR-008: 동의를 스키마로 강제
**결정**: `consents`에 동의 종류·주체·문서 버전·철회 시각을 기록하고 `voice_profiles.consent_id`를 NOT NULL로 둔다. 가족 음성은 가족 본인 동의, 해외 API 전송은 국외이전 요건, 연구 영상은 별도 동의로 분리한다.
**이유**: 음성과 입술 좌표를 보수적으로 민감정보로 취급한다. 동의 없는 처리가 존재할 수 없게 스키마로 막는다.
**트레이드오프**: 온보딩 동의 단계가 길어진다(보호자 손 사용 수 회). §8, §11.2, §11.4

### ADR-009: 학습 데이터 — AI Hub 사전학습 + 지인 무성 발화 + 실제 대상자 검증, 전부 국내
**결정**: 공용 인코더는 AI Hub 립리딩 데이터(1,107명 · 오디오 1,150시간)로 사전학습하고, 지인 참여자의 무성 발화로 적응·평가하고, 실제 대상자로 최종 검증한다. 저장·학습은 국내에서만 한다.
**이유**: AI Hub 이용정책은 영리 목적 연구·개발을 허용하지만 국외 반출은 별도 합의가 필요하다. AI Hub는 소리 낸 발화이고 60대 이상이 7%라 무성·고령 데이터를 따로 모아야 한다.
**트레이드오프**: Colab·해외 GPU를 못 쓴다. 동의서에 철회 범위(이미 학습된 모델은 제외, 이후 학습에서 제외)를 첫 수집 전에 넣어야 한다. 이용 조건은 수행기관 서면 확인 필요(W19). §10, §15

### ADR-010: 입력 표현(좌표 vs 입 영역 영상) 미확정 — 둘 다 수집
**결정**: 고정 문장 트랙은 입술 좌표를 쓴다. 자유 문장 입력은 좌표 모델과 입 영역 영상 모델의 CER 비교로 정하고, 결론 전까지 연구 영상 동의자에게서 좌표와 입 영역 크롭을 함께 모은다.
**이유**: 공개 최고 성능 모델은 입 영역 영상을 쓴다. 좌표만 모은 데이터는 나중에 영상으로 되돌릴 수 없다.
**트레이드오프**: 영상으로 가면 "영상은 단말 밖으로 안 나간다" 원칙이 흔들리고 GPU가 필요해진다. §15.3

### ADR-011: WebSocket 미사용 — 지속 연결은 Supabase Realtime
**결정**: 요청은 단발 HTTP로 한다. 학습 완료 같은 푸시는 클라이언트가 Supabase Realtime에 직접 붙는다.
**이유**: Vercel WebSocket은 Public Beta이고 연결이 단일 인스턴스에 고정되며 브로드캐스트가 안 된다.
**트레이드오프**: 실시간 채널이 Supabase에 의존한다. §5.2, §9

### ADR-012: 비상업 가중치·데이터 배제
**결정**: XTTS-v2(CPML), F5-TTS·Fish-Speech·Spark-TTS 가중치, Auto-AVSR·AV-HuBERT 가중치, LRS2/LRS3를 쓰지 않는다. IndexTTS 2는 회피한다.
**이유**: 코드 라이선스와 별개로 가중치·학습 데이터가 상업 이용을 막는다.
**트레이드오프**: 공개 립리딩 체크포인트를 쓸 수 없어 자유 문장 모델을 자체 학습해야 한다. 자체 호스팅 TTS 후보는 Qwen3-TTS·CosyVoice 2(Apache 2.0), Chatterbox(MIT). §6.2, §10
